Use-After-Free
检查代码中是否存在Use-After-Free（UAF）漏洞。攻击者可能利用已释放的内存进行进一步攻击。

具体审计要点：
- 检查指针是否在释放后继续使用
- 分析内存管理逻辑是否正确
- 验证双释放问题
- 检查引用计数是否正确
- 分析回调函数中的内存生命周期

常见漏洞模式：
- free(ptr); strcpy(ptr, "data"); // 释放后使用
- free(ptr); free(ptr); // 双次释放
- func(ptr); free(ptr); // 函数调用后释放，但函数内部可能保存了指针
- ptr = NULL; // 忘记置空可能被误用
- 回调中保存指针但对象已释放

CivetWeb特定场景：
- HTTP连接关闭后连接结构体被重用
- 请求处理回调中捕获的上下文已释放
- WebSocket连接关闭后消息处理
- 动态分配的结构体在请求结束后未正确释放
- 多线程环境下的竞态条件UAF

修复建议方向：
- 释放内存后立即置为NULL
- 使用智能指针管理内存生命周期
- 避免在函数外部保存栈指针
- 使用内存分配/释放配对的清晰模式
- 使用ASan/Valgrind等工具检测UAF

内存泄漏
检查代码中是否存在内存泄漏漏洞。长期的内存泄漏可能导致服务器资源耗尽，最终导致拒绝服务。

具体审计要点：
- 检查malloc/new后是否有对应的free/delete
- 分析错误处理路径是否正确释放资源
- 验证函数退出时是否释放所有分配内存
- 检查回调函数中的内存管理
- 分析长生命周期对象的内存管理

常见漏洞模式：
- malloc(x); return; // 分配后直接返回未释放
- if (error) { free(ptr); return; } else { // 未释放 }
- new char[size]; // C++中未配对delete
- ptr = malloc(); if (!ptr) return; // 错误路径未处理
- strdup(user_input); // 未释放返回的指针

CivetWeb特定场景：
- 请求处理函数中分配的内存未释放
- 连接结构体中的动态分配成员未清理
- 错误处理路径中的内存泄漏
- 回调函数中分配的资源未释放
- WebSocket消息处理内存泄漏

修复建议方向：
- 使用智能指针（C++）或引用计数
- 遵循谁分配谁释放的原则
- 在所有退出路径上释放资源
- 使用内存泄漏检测工具（Valgrind, ASan）
- 实施内存使用监控和告警

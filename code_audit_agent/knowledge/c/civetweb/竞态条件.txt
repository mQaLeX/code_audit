竞态条件
检查代码中是否存在竞态条件（Race Condition）漏洞。Web服务器处理并发请求时，竞态条件可能导致数据不一致或安全漏洞。

具体审计要点：
- 检查多线程共享资源的访问是否加锁
- 分析检查和使用之间是否存在TOCTOU问题
- 验证文件操作的原子性
- 检查信号处理函数中的异步问题
- 分析内存访问的顺序是否安全

常见漏洞模式：
- if (access(file)) { open(file); } // TOCTOU: 检查后使用
- if (!ptr) { ptr = malloc(); } // 检查后使用，中间可能被其他线程修改
- global_var++; // 非原子操作
- pthread_create(...); // 线程共享资源未保护
- 锁获取顺序不一致可能导致死锁

CivetWeb特定场景：
- 多个HTTP请求同时修改会话数据
- 连接池管理中的竞态条件
- 统计计数器并发更新
- 文件上传时的文件覆盖问题
- 配置文件重载时的竞态
- WebSocket多线程消息处理

修复建议方向：
- 使用互斥锁、读写锁保护共享资源
- 使用原子操作处理简单计数器
- 检查和使用操作应原子化
- 遵循一致的锁获取顺序避免死锁
- 使用线程安全的数据结构
- 使用ThreadSanitizer检测竞态条件

拒绝服务
检查代码中是否存在可能导致拒绝服务（DoS）的漏洞。Web服务器需要能够处理恶意请求而不崩溃。

具体审计要点：
- 检查资源分配是否有限制
- 分析循环是否有终止条件保护
- 验证递归调用是否有深度限制
- 检查内存使用是否可控
- 分析异常处理是否完善

常见漏洞模式：
- while(1) { read(sock, buf, size); } // 无终止条件
- recursive_func(depth); // 无递归深度限制
- malloc(large_size); // 无大小限制的内存分配
- for(i=0; i<user_count; i++) { process(); } // 循环次数可控
- strcpy(dst, src); // 缓冲区溢出导致崩溃

CivetWeb特定场景：
- 恶意构造的HTTP请求头导致内存耗尽
- 超大Content-Length导致内存分配过大
- 大量并发连接耗尽资源
- 特殊构造的WebSocket帧导致死循环
- 正则表达式回溯导致CPU耗尽（ReDoS）
- 路径解析中的无限循环
- 恶意构造的JSON/XML导致解析崩溃

修复建议方向：
- 对所有用户输入设置最大长度限制
- 使用资源配额和超时机制
- 实现连接数和请求频率限制
- 对复杂数据结构设置深度限制
- 使用安全的解析库并设置限制
- 实现请求超时和优雅降级
